01この装置が何をするか

SaaSのLPで使っている「斜めの直線バー」を、曲線に置き換えたものです。挙動（fixedレイヤ＋視差で追従）はそのまま引き継ぎ、形と意味だけを変えます。

要素直線バー（SaaS）成長の曲線（教育）
形直線・鋭角曲線・右上へ立ち上がる
意味速さ・システム・精度伸びる・積み上がる・上向き
描画最初から引かれている同じ（描画アニメーションは入れない）
動き視差で追従。加速する視差で追従。加速しない
色ブランド1色の濃淡3色（緑・青・黄）を低不透明度で重ねる

曲線が右上へ抜けることが本質です。左下から右上への上昇＝成長という読み方は説明不要で伝わるため、キャッチコピーに「伸びる」と書かなくても効きます。

02構造（HTML）

<body> 直下に追従レイヤを1つ置きます。FVの中ではなく body 直下です。fixed で貼り付けてスクロールに追従させるためです。

3本を別々の <div>・別々のSVGに分けているのは、1本ずつ違う速さで動かすためです。同じ速さだと奥行きが出ません。

<section class="fv"> … </section>   <!-- 中身は z-index:1 で上に -->
#growth{ position:fixed; inset:0; z-index:0; overflow:hidden; pointer-events:none; }

/* トラックは 220vh。上下に余りを持たせ、動かしても端が見えないようにする */
#growth .gl{ position:absolute; left:0; top:-60vh; width:100%; height:220vh;
             will-change:transform; }
#growth svg{ width:100%; height:100%; display:block; }
#growth path{ fill:none; stroke-linecap:round; vector-effect:non-scaling-stroke; }
  • aria-hidden="true" と pointer-events:none は必須。
  • パスの始点 -80・終点 1560 は viewBox（0〜1440）の外側です。端を画面外に逃がすことで、線端の丸みが画面内に見えないようにしています。ここは詰めないでください。
  • コンテンツ側には position:relative; z-index:1; を必ず付ける。付け忘れると曲線が文字の上に乗ります。

03ジオメトリ（曲線の設計）

viewBox は 0 0 1440 1584（＝220vh ぶん）。スクロール量0のとき画面に見えているのは y = 432 〜 1152 の帯です。下の座標はこのトラック座標系です。

パス役割speedd 属性
r1奥・最も太い0.30M-80 1182 C 420 1172, 980 992, 1560 552
r2中0.40M-80 1252 C 460 1232, 1020 1042, 1560 662
r3手前・最も細い0.52M-80 1312 C 500 1297, 1060 1152, 1560 792

見出しと重ならないことの担保： 画面左70%（x<1008）の範囲で、最も上を通る r1 でも、線の上端が画面高さの59%より下にあります（線幅の半分を含めた実測値）。見出しは左上〜左中央に置く前提なので構造的に交差しません。曲線は右端の30%で一気に立ち上がる設計で、この「後半で急に伸びる」形がそのまま成長の読みになります。

パスx=1008 での中心線幅の半分線の上端クリアランス
r165%43px59%見出し下端から約70px下
r276%32px72%十分
r392%22px89%十分

※位置は可視窓（FV1画面ぶん）の高さを100%とした比率。線幅は1440px幅時の値です。

この検証を必ずやること 見出しの外接矩形の中で曲線が最も濃く出る点を拾い、文字色とのコントラスト比が 4.5:1 以上あることを確認する。下回るならパスを下げる。太さで逃げないこと——太さを変えるとこの装置の印象そのものが変わります。見出しを右寄せ・中央寄せにする場合はこの保証が崩れるので、パスを引き直してください。

04カラーと太さ

パス色不透明度太さ（1440px時）意図
r1#5E9C80（セージ）.2686px最も太いので最も薄く
r2#7FB4D0（スカイ）.3263px中間
r3#EDAE42（サン）.3043px細いので少し強く

ブランドカラーに置き換える場合は 3色の明度差を保つことが条件です。同じ明度の3色を重ねると線が団子になり「上昇」が読めなくなります。明度差がとれないなら2本に減らしてください。

05スクロールの挙動

曲線は最初から引かれている

描画アニメーション（線が伸びていく演出）は入れません。 ページを開いた時点で3本とも完成しています。入るのはレイヤ全体の opacity フェードのみ（600ms）で、これは読み込み直後のチラつきを消すためのものです。

スクロールで「ついてくる」

fixed レイヤの中で、3本をそれぞれ違う速さで下方向へ translateY します。ページより遅く動くので、追いかけてくるように見えます。

translateY = scrollY × speed

r1（奥・太い）   speed = 0.30   ← 最もゆっくり
r2（中）         speed = 0.40
r3（手前・細い） speed = 0.52   ← 最も速い

奥ほど遅く動かすのが原則です。3本を同じ速さで動かすと、板が1枚ずれるだけになって奥行きが消えます。

加速させないこと scrollY × speed の1次式のままにしてください。SaaS版では係数を大きくして加速感を出していますが、教育系で加速する背景は「急かされている」印象になり、安心感と正面から衝突します。速度は一定です。

下のセクションに入り込ませない

fixed なので、そのままだと全セクションの背面に居座ります。独自の背景を持つセクション（濃色セクション・フッターなど）の手前でクリップして消します。

var stop = document.querySelector('.dark-section');   // 最初の"背景を持つ"セクション
var top  = stop.getBoundingClientRect().top;
growth.style.clipPath = 'inset(0 0 ' + Math.max(0, innerHeight - top) + 'px 0)';

06レスポンシブ（＝細くする）

最重要：太さを viewBox のスケールから切り離す preserveAspectRatio="none" で伸縮させると、通常の stroke-width は横方向に引き伸ばされて線が潰れます。パスに vector-effect:non-scaling-stroke を付けて、太さは CSS 側で完全に管理してください。これを外すと狭い画面で線がべったり太くなります。 
#growth path{ vector-effect: non-scaling-stroke; }

.r1{ stroke-width: clamp(18px, 6.0vw, 96px); }
.r2{ stroke-width: clamp(13px, 4.4vw, 70px); }
.r3{ stroke-width: clamp( 9px, 3.0vw, 48px); }

clamp なのでブレークポイントを書かずに連続的に細くなります。下の表は実際に出る値です。

スマホは「細くする」だけでは足りない preserveAspectRatio="none" で横を 1440→375 に潰すと、PC用パスの立ち上がりが右端15%に押し込まれ、画面上からほぼ消えます。太さではなくパスの問題なので、スマホ用のパスを別に用意して差し替えてください。スマホ用は傾きをゆるくして、画面幅いっぱいで上がるように引き直しています。あわせて3本→2本に減らします（幅が狭いと3本が詰まって1本の帯に見えるため）。

画面高さに対する比率。本文の下端は約68%地点なので、全域で重なりません。

07アクセシビリティ・パフォーマンス

  • prefers-reduced-motion: reduce で視差を止める。曲線は最初から引いてあるので、止めても絵は完成しています。
  • レイヤは aria-hidden="true"、pointer-events:none。
  • 動かすのは transform と opacity のみ。top や height は触らない。
  • スクロールハンドラは {passive:true} ＋ requestAnimationFrame で1フレーム1回に間引く。
  • will-change:transform は .gl に付ける。3枚だけなので付けっぱなしで問題ない。

08やってはいけないこと

  1. 描画アニメーションを足さない。 曲線は最初から引かれています。線が伸びる演出を入れると装置が主役になり、FVのコピーが負けます。
  2. 3本を同じ速さで動かさない。 奥行きが消えます。
  3. スクロールで加速させない。 05を参照。
  4. 見出しを横切らせない。 どれだけ薄くても読みにくくなります。パスを下げるのが正解で、不透明度で逃げると今度は線が見えなくなります。
  5. モバイルでPC用パスをそのまま潰さない。 立ち上がりが右端に寄って消えます。専用パスへの差し替えと本数削減の両方が必要です。
  6. vector-effect を外さない。 06を参照。線が横に潰れます。
  7. 下のセクションに入り込ませない。 05のクリップを必ず入れる。
  8. 3色の明度を揃えない。 04を参照。上昇が読めなくなります。

09JavaScript（全文）

(function(){
  var growth = document.getElementById('growth');
  if(!growth) return;

  var reduce  = matchMedia('(prefers-reduced-motion:reduce)').matches;
  var layers  = [].slice.call(growth.querySelectorAll('.gl'));
  var stop    = document.querySelector('.dark-section'); // 無ければ null でよい
  var ticking = false;

  function frame(){
    ticking = false;
    var y = window.pageYOffset || 0;

    if(!reduce){
      layers.forEach(function(el){
        var s = parseFloat(el.getAttribute('data-speed')) || 0.3;
        el.style.transform = 'translate3d(0,' + (y * s) + 'px,0)';
      });
    }

    // 独自の背景を持つセクションの手前で切る
    if(stop){
      var top = stop.getBoundingClientRect().top;
      growth.style.clipPath = 'inset(0 0 ' + Math.max(0, innerHeight - top) + 'px 0)';
    }
  }

  addEventListener('scroll', function(){
    if(!ticking){ ticking = true; requestAnimationFrame(frame); }
  }, {passive:true});
  addEventListener('resize', frame);

  frame();
  requestAnimationFrame(function(){ growth.classList.add('is-ready'); });
})();

10チェックリスト（実装後）

  • ページを開いた時点で3本とも引かれている（線が伸びる演出が無い）
  • スクロールすると3本がついてくる。奥の太い線ほどゆっくり動いている
  • スクロール速度を上げても加速しない
  • 1600 / 1440 / 1024 / 768 / 375px で線が細くなっていく
  • 767px以下でスマホ用2本に切り替わり、画面幅いっぱいで上がっている
  • スマホでFVが全画面になっていて、曲線が本文の下に収まっている
  • 見出しの上を線が通っていない。コントラスト比 4.5:1 以上
  • 濃色セクション／フッターに線が入り込んでいない
  • コンテンツが必ず線より前面にある（z-index の付け忘れが無い）
  • OS設定で「視差効果を減らす」をONにすると、動かないが絵は完成している
